## 優先度の考え方

「店舗の負担軽減」と「永続利用（リピート・お直し・紹介）」に直結するかを基準に、
以下の2軸でスコアリングした。

- **負担軽減スコア**：繁忙期に何人・何時間の工数削減になるか（1〜5点）
- **永続利用スコア**：翌年・3年後も使い続ける理由になるか（1〜5点）

#### F-01: 繁忙期シーズンダッシュボード

**なぜ必要か**
繁忙期（11月〜4月）のスタッフは「今日何をすべきか」が分からず、紙のToDoリストに頼っている。
毎日の「今日の採寸予約数」「未完了の受注件数」「引渡し待ち件数」が1画面で見えれば、
朝礼の時間を0にして即動ける。

**仮説検証**
- 「朝、まず何から確認しますか？」→ほぼすべての店舗で「予約台帳」と「昨日の引渡し状況」
- デジタル化すると「見落とし件数がゼロになった」という事例多数（T&Y調査より）

**機能要件**
| 項目 | 内容 |
|---|---|
| 表示エリア | 管理画面トップに「今日のサマリー」バナーを追加 |
| 今日の予約数 | 本日の採寸予約（status=reserved, date=today）の件数 |
| 対応待ち件数 | 「受注済み・未発注」の制服注文件数 |
| 引渡し準備完了 | 「入荷済み・未連絡」件数（お客様への完了通知を出していない件数） |
| 締切アラート | 学校ごとの発注締切まで「X日」の警告バッジ（赤3日以内/黄7日以内） |
| シーズン判定 | 現在日付から自動的にシーズン（繁忙期/通常期）を判定して背景色を変える |

**UI設計方針**
- 管理画面（admin/page.tsx）のTopセクションに新規コンポーネント`<SeasonDashboard>`を追加
- 既存のQue表示・ボトムナビは変更しない
- 数字をタップすると該当一覧画面へジャンプ

**負担軽減スコア**: 5/5（毎朝の確認作業が数秒に短縮）  
**永続利用スコア**: 5/5（毎年11月にシステムを開くきっかけになる）

#### F-02: 学校別締切アラート

**なぜ必要か**
学校ごとに異なる「採寸受付締切」「発注締切」「入学式必着日」を担当者の記憶に頼っている。
1件でも発注締切を過ぎると、入学式に制服が間に合わない重大事故になる。

**仮説検証**
- 「締切ミスはありますか？」→「年に1〜2件は電話確認ミスがある」（聞き取り複数店舗）
- デジタル締切管理を導入した店舗では「締切超過ゼロ」を達成している

**機能要件**
| 項目 | 内容 |
|---|---|
| 学校マスターへの追加フィールド | `order_deadline`（発注締切日）、`pickup_deadline`（引渡し完了目標日） |
| アラート表示 | 管理トップに「締切が近い学校」リストを表示（3日以内：赤、7日以内：黄） |
| LINE通知 | 締切3日前にスタッフへLINEプッシュ通知（push-admin API経由） |
| 過去の締切 | 締切日を過ぎた場合は「期限切れ」バッジで表示（削除はしない） |

**UI設計方針**
- `<SchoolDeadlineAlert>`コンポーネントを新規作成
- 管理ダッシュボードの上部、SeasonDashboardの下に配置
- 学校マスター（`/[storeId]/admin/`内）のUIに締切日フィールドを追加

**負担軽減スコア**: 5/5（重大事故防止＝クレーム対応コスト削減）  
**永続利用スコア**: 4/5（毎年8月に学校マスターを更新する習慣が生まれる）

#### F-03: 在校生年次フォロー自動化（LINE通知スケジュール）

**なぜ必要か**
入学時に登録した生徒の「学年進級」に合わせて、自動的にLINE通知を送る仕組みがない。
「夏服の受付が始まりました」「2年生になりましたね。ワイシャツの補充はいかがですか？」
といった文脈ある通知が自動化されると、在校生の継続購買率が上がる。

**仮説検証**
- 在校生の追加購買は平均1人あたり年間3,000〜8,000円（業界推定）
- 能動的にフォローしている店舗は在校生購買率が15〜25%高い（T&Y調査）

**機能要件**
| 項目 | 内容 |
|---|---|
| 入学年の記録 | CRM顧客レコードに`admission_year`（入学年度）フィールド追加（既存children テーブルに追加） |
| 通知テンプレート | 「夏服受付開始」「2年次ワイシャツ案内」「3年次卒業式案内」の3種類を標準提供 |
| 自動発火条件 | `admission_year`から現在年度を計算して学年を自動判定 → 設定日に通知 |
| 管理画面 | `/[storeId]/admin/` 内に「フォロー通知設定」タブを追加（通知テンプレート・送信日設定） |
| 手動送信 | 一覧から対象者を選んで「今すぐ送信」も可能に |

**負担軽減スコア**: 4/5（手動フォロー作業が不要に）  
**永続利用スコア**: 5/5（3年間自動でフォローが続くためシステムを解約できなくなる）

#### F-04: 採寸会チェックリスト（イベント前日準備）

**なぜ必要か**
採寸会の準備（会場レイアウト・持ち物・スタッフ配置）が担当者の記憶に頼っている。
前日チェックリストをデジタル化することで、新人・バイトスタッフでも準備漏れがなくなる。

**機能要件**
- `/[storeId]/admin/`内に「採寸会準備」ページを追加
- 学校名・開催日・担当スタッフを登録
- チェックリスト項目（商品マスタから自動生成＋手動追加）
- 当日の進捗（受付済み人数リアルタイム表示）

**負担軽減スコア**: 4/5  
**永続利用スコア**: 3/5

---

#### F-05: 在庫引当・発注数量自動集計

**なぜ必要か**
受注データが揃っているにも関わらず、発注集計が手作業（エクセル・正の字カウント）のため
繁忙期の深夜作業が発生している。受注データから自動的に「品番別・サイズ別の発注数量」を
集計するだけで、発注作業が数時間→数分に短縮される。

**機能要件**
- `/[storeId]/admin/purchase/`ページに「発注集計」セクションを追加
- 受注済みデータを品番・サイズ別に集計してCSVエクスポート
- 既存在庫数との差分から「正味発注数量」を算出
- 発注書PDF出力（メーカー別テンプレート）

**負担軽減スコア**: 5/5  
**永続利用スコア**: 4/5

---

#### F-06: 保護者向けマイページ（購入履歴・採寸記録の閲覧）

**なぜ必要か**
「前回いくつのサイズを買いましたか？」という問い合わせが繁忙期に殺到する。
保護者が自分でLINEマイページから確認できると、電話問い合わせが激減する。

**機能要件**
- LIFF上で保護者が自分の購入履歴・採寸サイズを閲覧できるページ
- 「前回購入品一覧」「採寸時のサイズ記録」「次回の予約リンク」を表示
- 兄弟姉妹の切り替えタブ

**負担軽減スコア**: 4/5  
**永続利用スコア**: 5/5
