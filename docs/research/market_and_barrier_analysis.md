# 学生服DXアプリ 市場リサーチ＆競合ブロック戦略

> 作成日: 2026-06-24  
> 対象: 学生服・制服販売店向け LINE連携予約・採寸・お直し管理システム

---

## 1. 学生服市場の現状と課題

### 1-1. 市場規模と構造変化

| 指標 | 内容 |
|---|---|
| 市場規模（推定） | 約1,500〜2,000億円（学生服＋体操服＋スクール小物含む） |
| 少子化の影響 | 年間出生数は2024年に初の70万人台割れ。2030年代には中学入学者が現在比15〜20%減少見込み |
| ジェンダーレス制服 | 2023年時点で全国の中学・高校の約30%以上が「スラックス選択制」を導入。スカート/スラックス両商品在庫を持つ必要あり |
| 販売店の高齢化 | 全国の専門店オーナーの平均年齢は60代前後。後継者不在による廃業ラッシュが始まっている |
| 人手不足 | 繁忙期（1〜3月）の採寸スタッフ確保が年々困難に。パートタイム採用コスト増大 |

### 1-2. 業界固有の3大課題（DX化が遅れる理由）

**① 繁忙期の超集中**
- 合格発表（2月上旬）〜入学式（4月上旬）の約8週間に、年間売上の50〜70%が集中
- この期間に電話問い合わせ・来店・採寸・発注・引渡しが同時発生
- 「紙伝票+電話+FAX」体制では対応しきれず、ミス・残業・クレームが急増

**② 学校ルールの複雑性**
- 学校ごとに「指定品目」「サイズ表記」「刺繍位置・文字色」「締切日」が異なる
- 1店舗が担当する学校数は平均20〜50校。ルールを全スタッフが把握するのは不可能
- 担当者退職・異動でノウハウがゼロリセットされるリスク

**③ 3年間のライフサイクル管理**
- 入学→成長→卒業の3年間を通じて「裾上げ・袖詰め・サイズ交換・夏服追加」が発生
- 購入履歴・採寸サイズが手元にないと、来店のたびに再採寸が必要
- 在校生へのフォローアップ通知（夏服受付開始など）が手動で困難

## 2. 競合システムの分析

### 2-1. 主要競合カテゴリと特徴

| 競合カテゴリ | 代表システム例 | 強み | 弱み |
|---|---|---|---|
| 汎用POSシステム | アラジンオフィス、Bシステム | 在庫管理・売上集計が得意 | 学校別ルール対応なし。LINE連携なし |
| 予約管理SaaS | RESERVA、Coubic | 予約受付がシンプル | 制服特有の採寸・加工フローなし |
| 制服専用受注 | T&Y、ユニネク | 業界知識が豊富 | 高額導入費、クラウド化遅れ |
| 大手EC・カタログ | カンコー学生服EC | ブランド力がある | 地域店舗との競合、スタッフ接客不可 |
| 汎用kintone | kintoneカスタム | 柔軟性が高い | 構築コスト大、保守できる人材不足 |

### 2-2. 競合の共通弱点（攻撃ポイント）

1. **LINE連携がない・弱い**：保護者は日常的にLINEを使っているが、競合の多くはメール・電話対応のみ
2. **学校別ルールのDB化がない**：スタッフが毎回マニュアルを参照する手間が解消されていない
3. **採寸→発注の一気通貫フローがない**：採寸データと受注データが別システムで2重入力が必要
4. **在校生フォローが手動**：入学後3年間の継続購買促進ができていない
5. **スマホ操作に最適化されていない**：タブレット・スマホでの採寸会での入力が難しい

## 3. 競合ブロック戦略（参入障壁の構築）

### 3-1. データの囲い込み（最強の参入障壁）

**学校別ルールDB（最大の差別化）**
- 各店舗が使い込むほど「その店舗だけの学校別ルールDB」が充実していく
- 学校ごとの指定品・サイズ表記・刺繍仕様・締切・注意事項をすべてシステム内に蓄積
- 競合他社への乗り換えコスト = このDBを再構築するコスト（数年分のデータ）
- **OCRによる自動取込**で初期登録ハードルを大幅に下げ、早期データ蓄積を促進

**顧客・家族の採寸サイズ履歴**
- 生徒1人あたり3年間のサイズ変化データが蓄積
- 兄弟姉妹データも連携し、次子の採寸時に「前回の成長データ」を参考提示
- このデータが蓄積されるほど接客精度が上がり「この店に来れば安心」の体験が強まる

### 3-2. オペレーションの融合（ロックイン）

**スタッフの動線最適化**
- 採寸会の「受付→採寸→受注入力→会計→引渡し予約」の全工程をスマホ1台で完結
- スタッフが本システムに慣れると、他システムへの移行コストが心理的に高くなる
- QRコード受付・番号札・呼び出し機能で採寸会の現場運営そのものをシステムが担う

**LINE公式アカウントの統合**
- 保護者が「入学時にLINE友達登録」→以降すべての通知（採寸完了・引渡し準備OK・夏服受付）がLINEで届く
- 保護者がLINEアカウントを解除しない限り、3年間の接点が自動的に継続
- LINE経由の予約・追加注文・お直し申込みが定着すると、他チャネルへの移行が起きない

### 3-3. 永続利用の仕組み（チャーン防止）

**年間イベントカレンダーとの連動**
- システム内に「店舗の年間業務カレンダー」を持つ
- 10月：学校マスター更新アラート → 11月：予約受付開始 → 3月：発注締め確認 → 5月：夏服受付
- 毎年同じサイクルで「次の作業」をシステムが案内することで、年間を通じた利用が定着

**在校生フォローの自動化**
- 入学年を登録した生徒に対して「2年生になりました。夏服の準備はお済みですか？」等のLINE通知を自動送信
- 「3年生の卒業式シーズン、白いシャツの準備を忘れずに」といった文脈に合ったメッセージ
- これにより店舗が能動的に動かなくても在校生の再来店が促進される

**紹介経済の設計**
- 購入完了後にLINEクーポンを自動発行し「次のご来店・ご紹介でご利用いただけます」
- 学校PTA・担任経由の口コミを仕組みとして設計

## 4. 現行アプリの強み評価

現在のコードベース（`app/[storeId]/`以下）を分析した結果：

| 機能 | 実装状況 | 競合優位性 |
|---|---|---|
| LINE LIFF連携 | 実装済（`lib/liff.ts`） | 高：LINEベースのUXは業界最先端 |
| 学校マスターDB | 実装済（`types/school.ts`, OCR対応） | 最高：これが最大の参入障壁 |
| 採寸パネル | 実装済（`school_measurement`フラグ） | 高：競合にほぼない機能 |
| お直し管理 | 実装済（repairフロー） | 中：競合POSも持つが連携が弱い |
| 顧客CRM | 実装済（`types/crm.ts`） | 高：採寸履歴+購買履歴の統合が優位 |
| リアルタイム待ち管理 | 実装済（queue管理） | 中：新規性高いが繁忙期需要がある |
| 在庫管理 | 未実装 | 要開発：競合POSが強い領域 |
| 発注・集計自動化 | 未実装 | 要開発：最もペイン大きい領域 |
| 在校生フォロー通知 | 部分実装（LINE通知あり） | 要強化：年間カレンダー連動が必要 |
| シフト管理 | フラグあり・未本格実装 | 中：繁忙期スタッフ確保に直結 |

## 6. 次ステップへの提言

ステップ2（機能要件定義）では、以下3点を最優先に設計すること：

1. **繁忙期シーズンダッシュボード**：11月〜3月の「今日やること」を1画面で可視化
2. **学校別締切カレンダーアラート**：採寸締切・発注締切が近づいたら自動通知
3. **在校生年次フォロー自動化**：入学年登録からLINE通知の自動スケジューリング

これらはいずれも「データが蓄積されるほど価値が高まる」機能であり、競合ブロックとして最も有効に機能する。
